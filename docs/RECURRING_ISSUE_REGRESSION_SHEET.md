# Shoonaya recurring-issue regression sheet

**Audit date:** 2026-10-12  
**Scope:** Native app (`shoonaya-mobile`) and its canonical backend (`Sanatan Sangam/Shoonaya`). The backend web/PWA UI is retired and is out of scope.  
**Purpose:** Keep the recurring failures reported during development from returning unnoticed, and stop avoidable EAS builds before they consume build time.

This is an incident-derived checklist, not a claim that every app behavior or database write has already been tested. “Covered” means a relevant automated regression test exists and passed in the focused run recorded below. It does not mean a real Supabase project, push provider, App Store build, or physical device was exercised.

## Current audit result

The recurring incident paths now have focused persistence contracts and a prescribed pre-EAS gate. Kundali route tests verify the saved response against the inserted row, owner derivation, guest session scoping, primary-index fallback, and missing read-back failure. Location sync requires an owner-scoped update and exact row read-back; SQL tests cover account isolation. Migration drift is checked read-only, and store/OTA wrappers run asset, build metadata, typecheck, Native suite, and linked migration checks. A broad source-level inventory of every database mutation across both repositories is still not complete, and isolated SQL suites could not run here because Docker is unavailable.

The supported Native EAS wrappers now run `prebuild:verify` (asset and build-metadata checks, typecheck, full Native suite); store/OTA wrappers also require a clean, committed backend migration tree and a read-only linked migration-history check. GitHub Actions runs the same Native gate on pull requests and main pushes. A direct CLI/dashboard invocation can bypass npm wrappers, so branch protection must require the workflow and release operations must use the documented entry points.

## Minimal pre-EAS release gate

The target is to fail in minutes before a build enters the EAS queue. Do not boot a second cloud database or create a paid ephemeral branch for each build; use a warm, isolated CI Supabase test database (or local disposable stack) with deterministic seed/cleanup.

1. **Always, Native:** typecheck, full Native regression suite, asset-format check, and app-config/build-number validation.
2. **Always, backend contract:** run the focused Native-facing API contract/auth/calendar/notification tests against the code revision expected to serve the build. If backend code is unchanged from the last verified compatible deployment, reuse its immutable CI result.
3. **Always, persistence smoke:** execute one fast round-trip per database-write domain listed above, including Kundali and confirmed location. Verify read-back, owner isolation and idempotent retry; no production writes.
4. **When migrations or SQL/RPC/RLS change:** start/reset the isolated Supabase test database, apply migrations from a clean state, run the relevant SQL tests plus migration postconditions, and fail on unexplained local/remote history drift before deploy/build.
5. **Before EAS starts:** require all preceding checks green in the same commit SHA. The EAS job must depend on the gate; package scripts alone are bypassable and are not an enforcement mechanism.
6. **After EAS:** run a short device smoke on the exact artifact/build number. Exercise cold launch, sign-in/restore, Home calendar, Profile, one write/read-back flow, and one update path. Push delivery is only claimed after physical-device/provider receipt evidence.

Do not rerun the whole backend suite for every Native-only copy or layout change. Do not skip the focused persistence round-trips, typecheck, Native suite, or asset check before a build. Use changed-contract detection to add backend tests when shared API, auth, schema, calendar, notification, or profile code changes.

## Audit evidence recorded for this sheet

On 2026-10-12, the Native gate passed: **1,334 tests across 215 suites**, typecheck, build metadata, and asset validation (456 images). The full backend suite passed: **1,495 Vitest tests across 202 files plus 43 Node contract tests**, with `tsc --noEmit` clean. Migration-drift parser tests passed **3/3**. Added route-focused cases are included in the backend totals.

The SQL persistence/RLS tests are written but were not executable here: `supabase status` reported no Docker daemon at `~/.docker/run/docker.sock`. The linked migration preflight was not run because the new local migration is intentionally uncommitted and would be reported as drift. No production query, migration, notification, build, or deployment was performed. The backend working tree still contains unrelated uncommitted marketing work; it was not edited or staged in this task.
